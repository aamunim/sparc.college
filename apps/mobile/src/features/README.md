# features/

প্রতিটা ফিচার নিজের ফোল্ডারে (গাইডলাইন §৭.১):

```
features/<name>/
  api.ts          ডেটাবেস কল — শুধু এখানে (getSupabase() from '@/platform/supabase')
  hooks/          TanStack Query হুক (api.ts ব্যবহার করে)
  components/     এই ফিচারের UI অংশ
  screens/        পুরো স্ক্রিন — src/app/ এর রুট এগুলো import করে
  types.ts        টাইপ ও zod স্কিমা
  index.ts        পাবলিক API — অন্য ফিচার শুধু এটা import করবে
```

নিয়ম (ESLint দিয়ে প্রয়োগ):

- অন্য ফিচারের ভেতরের ফাইল নয়, শুধু `@/features/<name>` থেকে import।
- ফিচারের নিজের ভেতরে relative import (`./api`)।
- `screens/` আর `components/` সরাসরি Supabase ডাকবে না।
- কোনো লেখা সরাসরি নয় — `t('…')`; কোনো রং সরাসরি নয় — `ui/` টোকেন।

## এখন যে ফিচারগুলো আছে

| ফিচার | কী করে |
|---|---|
| `session` | লগইন অবস্থা; ইউজার বদলালে সব ক্যাশ মোছে |
| `access` | `my_access()`, সক্রিয় প্রতিষ্ঠান (ইউজারভেদে সেভ), প্রতিষ্ঠান বদল (ক্যাশ + Realtime মোছে), `useCan()`, ফিচার ফ্ল্যাগ |
| `app-update` | পুরনো ভার্সনে "আপডেট করুন" স্ক্রিন (লগইনের আগেও) |
| `home` | হোমের মেনু রেজিস্ট্রি (পারমিশন/ফ্ল্যাগ দেখে ফিল্টার) |
| `dev-login` | শুধু `appEnv = dev`-এ seed ইউজার দিয়ে লগইন — ফেজ ২-এ আসল লগইন এলে সরবে |

## পারমিশনের নিয়ম

- UI-তে কিছু দেখানো/লুকাতে `const can = useCan(); can('member.read')` — **কখনো role নাম তুলনা নয়**।
- `can()` শুধু UI-র জন্য। আসল নিরাপত্তা ডেটাবেসে (RLS, `has_permission`)। sensitive পারমিশন (যেমন `role.assign`) ডেটাবেস MFA ছাড়া মানবে না, যদিও মেনু দেখাতে পারে।
- query key সবসময় `[userId, institutionId, …]` দিয়ে শুরু (অন্য ইউজার/প্রতিষ্ঠানের ক্যাশ যেন না মেশে)।
