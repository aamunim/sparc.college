## বিস্তারিত

### D3a — অ্যাডমিন প্যানেল: Expo Web বনাম Next.js (2026-11-03)

**প্রেক্ষাপট:** D3-এ অ্যাডমিন প্যানেলের জন্য Expo Web বেছে নেওয়া হয়েছিল। পরে প্রশ্ন উঠল, Next.js কেন নয়।

**সংশোধন:** v3 প্ল্যানে বলা হয়েছিল Next.js মানেই Node সার্ভার আর মাসিক হোস্টিং খরচ। এটা পুরোপুরি ঠিক নয়। Next.js-কে **static export** (`output: 'export'`) মোডে বিল্ড করলে সার্ভার লাগে না; Namecheap বা Cloudflare Pages-এ ফ্রি হোস্ট করা যায়। Supabase সরাসরি ব্রাউজার থেকে কাজ করে, আর গোপন কাজ Edge Function-এ হয়, তাই অ্যাডমিনের জন্য static export যথেষ্ট। **অর্থাৎ খরচ বা হোস্টিং আর সিদ্ধান্তের কারণ নয়।**

**আসল পার্থক্য:**

| বিষয় | Expo Web | Next.js (monorepo + static export) |
|---|---|---|
| কোডবেস | একটা; লগইন, পারমিশন, ভাষা, ডেটা কল একবার লেখা | দুইটা অ্যাপ; shared package (`packages/core`) লাগবে |
| কোর্স বানানোর স্ক্রিন (মোবাইল + ওয়েব দুই জায়গায় লাগে) | একবার বানালেই হয় | দুইবার, বা শুধু একটা প্ল্যাটফর্মে |
| ডেটা-ভারী অ্যাডমিন (বড় টেবিল, চার্ট, রিপোর্ট, মডারেশন) | `.web.tsx`-এ ওয়েব লাইব্রেরি দিয়ে সম্ভব, বাড়তি পরিশ্রম | shadcn/ui, TanStack Table, Recharts, অ্যাডমিন টেমপ্লেট সরাসরি |
| ডেস্কটপ UX (শর্টকাট, ড্র্যাগ-ড্রপ) | নিজে বানাতে হবে | সহজ |
| শেখা ও সেটআপ | কম | App Router, monorepo; ফেজ ০-এ ২–৩ দিন বেশি |
| ডেভেলপার পাওয়া | React Native জানা লোক কম | Next.js জানা লোক অনেক |
| পাবলিক সাইটের SEO / শেয়ার প্রিভিউ | দুর্বল | ভালো |
| হোস্টিং খরচ | শূন্য | শূন্য (static export) |

**কখন কোনটা:**
- **Expo Web:** একা বা React Native-কেন্দ্রিক ছোট টিম; দ্রুত MVP।
- **Next.js:** ওয়েব ডেভেলপার আছেন বা নেওয়া হবে; অ্যাডমিন প্যানেল বড় ও জটিল হবে; পাবলিক মার্কেটিং সাইট গুরুত্বপূর্ণ।

**বিকল্প:**
- **ক)** Expo Web-ই থাকবে (D3 অপরিবর্তিত)।
- **খ)** শুরু থেকেই Next.js, monorepo-তে: `apps/mobile`, `apps/admin`, `packages/core`।
- **গ)** সিদ্ধান্ত ফেজ ৩ পর্যন্ত খোলা; তবে ফেজ ০ থেকেই নিয়ম — `src/core`-এর ডেটা কল (api), zod স্কিমা, পারমিশন লজিক আর ভাষার ফাইল React Native-নির্ভর হবে না, যাতে পরে সরাসরি shared package-এ নেওয়া যায়।

**প্রস্তাবিত:** গ) — এতে এখন কোনো খরচ নেই, আর ফেজ ৩-এ যেকোনো দিকে যাওয়া যাবে কিছু না ভেঙে।
