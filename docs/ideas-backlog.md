# আইডিয়া ব্যাকলগ

নতুন আইডিয়া এখানে লিখুন। চলমান ফেজের মাঝে কোনো আইডিয়া ঢোকানো হবে না। প্রতিটা আইডিয়ার ইমপ্যাক্ট চেক হবে (`DEVELOPMENT-GUIDE.md` §১৫), তারপর কোন ফেজে যাবে তা `decisions-log.md`-এ লেখা হবে।

| আইডিয়া | ইমপ্যাক্ট চেক (content type / rule type / পারমিশন / সেটিং / নতুন মডিউল) | প্রস্তাবিত ফেজ | অবস্থা |
|---|---|---|---|
| পরীক্ষার সময় ক্যামেরায় মাঝেমধ্যে ছবি তোলা | নতুন মডিউল + সম্মতির ফ্লো | ১৪-এর পরে | অপেক্ষমাণ |
| লাইভ প্রক্টরিং (ভিডিও কলে নজরদারি) | নতুন মডিউল | ১৪-এর পরে | অপেক্ষমাণ |
| অ্যাপের নিজস্ব লাইভ ক্লাস (Zoom/Meet-এর বদলে) | নতুন content type (`live_native`) | ১৪-এর পরে | অপেক্ষমাণ |
| সুরক্ষিত ভিডিও হোস্টিং (YouTube-এর বদলে) | নতুন content type | ১৪-এর পরে | অপেক্ষমাণ |
| পরীক্ষার জন্য Play Integrity API | সেটিং + Edge Function | ১৪ | অপেক্ষমাণ |
| প্রচার ট্র্যাকিং (UTM, রেফারেল কোড) — ফেসবুক/ইউটিউব থেকে কে এল | সেটিং + events | ১৪ | অপেক্ষমাণ |
| AI ফিচার (যেমন নম্বর দেওয়ায় সাহায্য, পরামর্শ) — এলে guardrails প্রথম দিন থেকে: সব কাজ সার্ভারে/ব্যাকগ্রাউন্ডে, key Vault-এ, নাম/ফোন নয় (কোড), শিশুর ডেটা কখনো নয়, ইউজারের লেখা শুধু ডেটা হিসেবে (prompt injection), আউটপুট JSON schema-বাঁধা, প্রতিষ্ঠানপ্রতি বাজেট (৮০% সতর্কতা, ১০০% বন্ধ), দাম ও মডেল কনফিগে, চুপচাপ fallback নয় | নতুন মডিউল | ১৪-এর পরে | অপেক্ষমাণ |
| বাইরে-যাওয়া webhook / ভেতরে-আসা API — এলে: প্রতিটা webhook-এর আলাদা HMAC secret, timeout, back-off, অনেকবার ব্যর্থ হলে নিজে বন্ধ, ডেলিভারি লগ; API key প্রতিষ্ঠান আর permission registry-র scope-এ সীমিত, rate limit, অডিট | নতুন মডিউল | ১৪-এর পরে | অপেক্ষমাণ |
| রেফারেল প্রোগ্রাম — এলে: পুরস্কার শুধু টাকা আসার পর, রিফান্ডে ফেরত, নিজেকে রেফার আটকানো, পাবলিক ফর্মে rate limit | নতুন মডিউল | ১৪ | অপেক্ষমাণ |
